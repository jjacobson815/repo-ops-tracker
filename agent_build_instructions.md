# System Refactoring Instructions (for Sonnet 4.6)

This document contains instructions and reference code to refactor the current single-file `index.html` application into a modular, Docker-ready, file-persistent application.

Please read the instructions, files to create, and reference implementations below, then execute the refactoring.

---

## 1. Project Directory Layout

After refactoring, the project structure must look like this:

```
repo-ops-tracker/
├── Dockerfile
├── docker-compose.yml
├── package.json
├── server.js
├── data/
│   ├── tasks.json (auto-generated by server)
│   └── library.json (auto-generated by server)
├── public/
│   ├── index.html
│   ├── styles/
│   │   ├── variables.css
│   │   ├── layout.css
│   │   └── components.css
│   └── js/
│       ├── app.js
│       ├── api.js
│       └── components/
│           ├── dashboard.js
│           ├── board.js
│           ├── library.js
│           └── modal.js
```

## 2. Backend & Docker Files to Create

### 1. `package.json`
Set up a standard Node.js server environment:
```json
{
  "name": "repo-ops-tracker",
  "version": "1.0.0",
  "description": "Personal kanban board + AI-agent instruction library",
  "main": "server.js",
  "type": "commonjs",
  "scripts": {
    "start": "node server.js"
  },
  "dependencies": {
    "express": "^4.19.2"
  }
}
```

### 2. `Dockerfile`
Minimal Node production Dockerfile:
```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 8787
CMD ["node", "server.js"]
```

### 3. `docker-compose.yml`
Configure port mapping and bind volume mount for persistence:
```yaml
version: '3.8'
services:
  app:
    build: .
    ports:
      - "8787:8787"
    volumes:
      - ./data:/app/data
    environment:
      - PORT=8787
      - DATA_DIR=/app/data
```

### 4. `server.js`
An Express server that:
- Serves static files from `public/`.
- Manages tasks and library data in `data/tasks.json` and `data/library.json`.
- Seeds the library JSON array if `library.json` is empty.
- Exposes API routes:
  - `GET /api/tasks` -> Returns JSON array of tasks.
  - `POST /api/tasks` -> Saves/updates tasks (payload contains entire array of tasks).
  - `GET /api/library` -> Returns JSON array of instructions.
  - `POST /api/library` -> Saves/updates instructions (payload contains entire array of instructions).

## 3. Frontend Separation (Native ES Modules)

All files under `public/` should be modularized. The browser will import ES Modules directly using `<script type="module" src="js/app.js"></script>`.

### 1. `public/index.html`
Keep only structural skeleton, tabs, and modal HTML elements. Remove styles (move to `styles/`) and javascript (move to `js/`).

### 2. `public/styles/`
- **`variables.css`**: Store `:root` variables, colors, font rules, resets.
- **`layout.css`**: Store `.topbar`, `.tabs`, `.view`, `.dash-grid`, `.board`, `.lib-grid` placement rules.
- **`components.css`**: Styles for cards, buttons, modals, badges, toasts, inputs.

### 3. `public/js/api.js`
Create functions that make `fetch` requests to `/api/tasks` and `/api/library`:
```javascript
export async function getTasks() {
  const res = await fetch('/api/tasks');
  return res.json();
}
export async function saveTasks(tasks) {
  return fetch('/api/tasks', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(tasks)
  });
}
export async function getLibrary() {
  const res = await fetch('/api/library');
  return res.json();
}
export async function saveLibrary(library) {
  return fetch('/api/library', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(library)
  });
}
```

### 4. `public/js/app.js`
Import UI modules, manage global state, handle tab routing, and bootstrap application load:
```javascript
import { getTasks, getLibrary } from './api.js';
import { renderDashboard } from './components/dashboard.js';
import { renderBoard } from './components/board.js';
import { renderLibrary } from './components/library.js';

export let state = {
  tasks: [],
  library: [],
  currentTaskId: null,
  currentLibId: null
};

export async function initApp() {
  state.tasks = await getTasks();
  state.library = await getLibrary();
  renderAll();
}

export function renderAll() {
  renderDashboard(state.tasks);
  renderBoard(state.tasks);
  renderLibrary(state.library);
}

// Hook up navigation and filter event listeners...
```

### 5. `public/js/components/dashboard.js`
Encapsulates `renderDashboard()` logic from the old file.

### 6. `public/js/components/board.js`
Encapsulates `renderBoard()`, drag-and-drop, and card generation logic.

### 7. `public/js/components/library.js`
Encapsulates `renderLibrary()` and copy-to-clipboard logic.

### 8. `public/js/components/modal.js`
Encapsulates modal display, task modal, library modal form handling, and custom deletion confirmation dialog logic.
